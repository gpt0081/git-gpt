# Fjordfall Production Bible 0.2

# GAME VISION

한 줄 컨셉: 비바람 속 작은 섬에서 세 개의 분대를 짧고 정확한 명령으로 움직여 상륙 병력을 막는 실시간 전술 게임.

플레이어 감정: 제한된 공간을 읽고 병과를 맞는 위치에 배치했을 때 얻는 통제감과, 잘못된 한 번의 이동이 만드는 긴장.

디자인 기둥:
1. 분대 단위의 짧고 즉각적인 명령.
2. 지형·해안·병과 상성에 따른 명확한 전술 결과.
3. 저채도 디오라마와 최소 UI가 만드는 높은 가독성.

비목표:
- 참고 게임의 로고, 아이콘, 인물, 맵, 고유 명칭 또는 자산 복제.
- 개별 병사 직접 조작.
- v0.2 단계에서 캠페인·영구 성장·상점 완성.

# GDD

## 코어 루프
배치 → 적 수송선 접근 예측 → 분대 이동 → 자동 교전 → 능력 사용 → 승패 확인.

## 조작
분대 버튼 또는 분대 근처 지형을 눌러 선택한다. 섬 지형을 누르면 선택 분대가 진형을 유지하며 이동한다. 능력 버튼은 선택 병과의 기술을 사용한다.

## 병과
- 검병: 빠른 근접 공격과 회복형 방패 결집.
- 창병: 긴 근접 사거리와 주변 적을 밀어내는 창벽.
- 궁병: 장거리 공격과 최대 5명 대상 집중 사격.

## 승패
계획된 수송선이 모두 상륙한 뒤 살아 있는 적이 0명이면 승리한다. 모든 아군 분대가 전투불능이면 패배한다.

## v0.2 범위
섬 1개, 아군 3개 분대, 적 수송선 4척, 적 근접병, 배치·전투·결과 화면.

# ART BIBLE

레퍼런스 세트: 사용자가 제공한 24장의 모바일 화면 캡처를 R001~R024로 관리한다. 레퍼런스는 구조·가독성·카메라·색 관계만 분석하며 원본 자산을 포함하지 않는다.

- 카메라: 35~45도 하향 직교 카메라, 섬 전체가 한 화면에 보이는 디오라마 구도.
- 팔레트: 회녹색 바다와 지형, 짙은 자주색 수목, 밝은 회백색 건물. 부대 깃발만 고채도.
- 실루엣: 병사는 머리·몸·방패·무기가 작은 화면에서도 분리되어야 한다.
- 재질: 거친 무광. 강한 금속 반사와 사실적 PBR 질감은 금지.
- 환경: 비 줄기, 수면 원형 파문, 옅은 안개. 환경 효과가 병사 실루엣을 가리면 실패.
- UI: 큰 직사각형 버튼, 어두운 반투명 패널, 화면 가장자리 안전 여백 28px 이상.
- 금지 스타일: 포토리얼, 네온, 과도한 글로우, 참고 게임의 문양·초상·아이콘 직접 모사.

# ACCEPTANCE CRITERIA

- AC-001: 프로젝트를 열고 5초 이내에 배치 화면을 표시한다.
- AC-002: 세 분대 모두 선택과 지형 이동 명령을 받는다.
- AC-003: 전투 시작 이후 3초 이내 첫 수송선이 움직인다.
- AC-004: 네 척의 수송선이 각각 상륙 병력을 생성한다.
- AC-005: 세 병과의 공격 사거리가 육안으로 구분된다.
- AC-006: 살아 있는 병사는 분대 중심 기준 진형 위치로 복귀한다.
- AC-007: 일시정지 중 전투 시간과 이동이 정지한다.
- AC-008: 승리와 패배가 상호 배타적으로 한 번만 표시된다.
- AC-009: 10분 연속 실행 중 크래시와 무한 증가 객체가 없어야 한다.

# QUALITY RUBRIC

| 항목 | 가중치 | 통과 기준 |
|---|---:|---:|
| 기능 통과율 | 30 | 95% 이상 |
| 치명 버그 | 20 | 0건 |
| 시각 적합도 | 20 | 85점 이상 |
| 성능 | 15 | 평균 60 FPS, 1% low 45 FPS |
| 로그 건전성 | 10 | error/exception 0~2건 |
| 문서 일치도 | 5 | 100% |

시각 적합도는 구도·실루엣·색·가독성을 각 25점으로 평가한다. 이번 수동판은 기능 골격 검증이 우선이며 외부 에셋 완성도는 평가 대상에서 제외한다.

# DEFINITION OF DONE

- Unity 6.3 LTS에서 프로젝트가 열린다.
- 빨간 Console 오류가 없다.
- 수동 테스트 체크리스트 95% 이상 통과한다.
- 치명 버그 0건.
- 평균 60 FPS와 1% low 45 FPS를 목표로 한다.
- 변경된 기능이 GDD와 Acceptance Criteria에 반영된다.
- ZIP에는 Assets, Packages, ProjectSettings, 문서만 포함하고 Library/Temp/Logs를 포함하지 않는다.

# AUTONOMOUS LOOP POLICY

현재 단계는 인간 수동 테스트 루프다.

1. AI는 `ai/*` 브랜치에서 코드와 문서를 수정한다.
2. 사용자는 ZIP을 Unity에서 실행하고 스크린샷·재현 절차·평가를 전달한다.
3. 목표당 최대 수정 5회.
4. 동일 실패가 2회 반복되면 접근법을 바꾸거나 안정 버전으로 롤백한다.
5. 품질 점수가 2회 연속 하락하면 해당 변경을 중단한다.
6. 크래시, 데이터 손실, 프로젝트 열기 실패는 즉시 FAIL이다.
7. 기준 이미지, 품질 기준, 비목표를 AI가 임의로 완화하지 않는다.
